# TCP通讯测试服务端

## 项目概述
这是一个基于Netty框架的TCP服务端项目，用于模拟TCP通讯测试。服务端可以接收固定的字节数据并回复对应的固定字节数据，支持可配置的数据收发规则。

## 功能特性

- ✅ 基于Netty框架的高性能TCP服务端
- ✅ 可配置的固定字节数据收发
- ✅ 支持十六进制字符串格式配置
- ✅ 完整的日志记录和监控
- ✅ Spring Boot集成，支持热配置
- ✅ 多客户端连接支持
- ✅ 优雅的启动和关闭机制

## 快速开始

### 1. 环境要求
- Java 8+
- Maven 3.6+
- Spring Boot 2.7.5

### 2. 编译运行
```bash
# 编译项目
mvn clean compile

# 运行项目
mvn spring-boot:run
```

### 3. 配置说明

在 `src/main/resources/application.yml` 中配置TCP服务端参数：

```yaml
tcp:
  server:
    enabled: true          # 是否启用TCP服务端
    port: 8080            # 服务端监听端口
    # 接收的固定字节数据配置
    receiveData:
      - name: "心跳包"
        hexData: "01 02 03 04"
        enabled: true
      - name: "数据请求"
        hexData: "AA BB CC DD"
        enabled: true
    # 发送的固定字节数据配置
    sendData:
      - name: "心跳包"
        hexData: "05 06 07 08"
        enabled: true
      - name: "数据请求"
        hexData: "EE FF 00 11"
        enabled: true
```

### 4. 测试连接

使用telnet或其他TCP客户端工具连接服务端：

```bash
# 连接TCP服务端
telnet localhost 8080

# 发送配置的字节数据（十六进制）
# 例如发送心跳包: 01 02 03 04
# 服务端会回复: 05 06 07 08
```

## 配置参数详解

### TcpServerConfig 配置项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| enabled | boolean | true | 是否启用TCP服务端 |
| port | int | 8080 | 服务端监听端口 |
| receiveData | List<ByteDataConfig> | - | 接收数据配置列表 |
| sendData | List<ByteDataConfig> | - | 发送数据配置列表 |

### ByteDataConfig 配置项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| name | String | - | 数据名称/描述 |
| hexData | String | - | 十六进制字符串，如 "01 02 03 04" |
| enabled | boolean | true | 是否启用此配置 |

## 工作原理

1. **服务端启动**: 基于Netty创建TCP服务端，监听指定端口
2. **客户端连接**: 接受客户端连接，建立Channel通道
3. **数据接收**: 接收客户端发送的字节数据
4. **数据匹配**: 根据配置的receiveData列表匹配接收到的数据
5. **数据回复**: 找到匹配的配置后，根据name查找对应的sendData配置
6. **数据发送**: 将配置的回复数据发送给客户端
7. **日志记录**: 记录所有收发数据的详细信息

## 日志说明

项目使用Logback进行日志管理，日志文件保存在 `logs/tcp-proxy.log`：

- **INFO级别**: 服务启动、连接建立/断开等关键信息
- **DEBUG级别**: 详细的数据收发记录
- **WARN级别**: 配置错误、数据格式错误等警告
- **ERROR级别**: 连接异常、处理错误等错误信息

## 扩展功能

### 1. 添加新的数据配置

在 `application.yml` 中添加新的收发数据配置：

```yaml
tcp:
  server:
    receiveData:
      - name: "新命令"
        hexData: "FF EE DD CC"
        enabled: true
    sendData:
      - name: "新命令"
        hexData: "11 22 33 44"
        enabled: true
```

### 2. 自定义处理器

可以继承 `TcpServerHandler` 类，重写相关方法实现自定义逻辑：

```java
@Component
public class CustomTcpServerHandler extends TcpServerHandler {
    
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) throws Exception {
        // 自定义处理逻辑
        super.channelRead(ctx, msg);
    }
}
```

## 注意事项

1. **端口占用**: 确保配置的端口未被其他程序占用
2. **数据格式**: 十六进制字符串格式要正确，支持空格分隔
3. **配置匹配**: receiveData和sendData的name要一一对应
4. **网络防火墙**: 确保防火墙允许指定端口的连接
5. **日志监控**: 定期检查日志文件，监控服务运行状态

## 故障排查

### 常见问题

1. **服务端启动失败**
   - 检查端口是否被占用
   - 检查配置文件格式是否正确

2. **客户端连接失败**
   - 检查网络连接
   - 检查防火墙设置
   - 确认服务端已启动

3. **数据收发异常**
   - 检查十六进制数据格式
   - 查看日志中的错误信息
   - 确认配置的name匹配关系

### 3. 寄存器地址分析

从报文中可以识别出以下寄存器地址范围：

- **0x3FE5-0x3FE7**: 系统状态寄存器
- **0x07DC-0x07DF**: 运行参数寄存器  
- **0x100E-0x1017**: 配置参数寄存器
- **0x09A6-0x09A9**: 设备信息寄存器
- **0x00C8-0x00CD**: 用户设置寄存器
- **0x03B6-0x03BC**: 监控数据寄存器

### 4. 通讯特点

1. **主从模式**: 触摸屏作为主站，PLC作为从站
2. **轮询机制**: 定期查询设备状态和数据
3. **批量读写**: 支持多个寄存器的批量操作
4. **实时性**: 毫秒级响应时间
5. **可靠性**: 包含校验机制确保数据完整性

### 5. 与其他PLC协议对比

| 特性 | 当前协议 | Modbus TCP | EtherNet/IP | Profinet |
|------|----------|------------|-------------|----------|
| 命令码 | 0x11,0x14,0x17 | 0x01,0x03,0x06 | 0x4B,0x4C,0x4D | 0x00,0x01,0x02 |
| 数据格式 | 小端序 | 大端序 | 大端序 | 大端序 |
| 地址范围 | 16位 | 16位 | 32位 | 16位 |
| 最大长度 | 256字节 | 256字节 | 1500字节 | 1400字节 |
| 校验方式 | 简单校验 | CRC16 | 无 | 无 |
